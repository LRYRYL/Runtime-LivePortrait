## 权威依据：torch 自己的校验规则

**这轮我在本机 torch 头文件里找到了确切的校验代码**
（`site-packages/torch/include/ATen/native/GridSamplerUtils.h`），不必再靠试错猜形状：

```cpp
// 第 49-52 行
TORCH_CHECK(
  grid.size(-1) == input.dim() - 2,
  "grid_sampler(): expected grid to have size ", input.dim() - 2, " in last "
  "dimension, ...");

// 第 80-84 行（check_grid_sampler_3d）
TORCH_CHECK(
  input.dim() == 5 && input.dim() == grid.dim(),
  "grid_sampler(): expected 5D input and grid with same number of dimensions, ...");
```

由此得到**确切规则**：

| 输入 rank | 网格末维必须是 | 说明 |
|---|---|---|
| 4 | 2 | 2D |
| 5 | 3 | 3D 体素 |
| 6 | **4** | （也是 3D，但用四坐标形式）|

这解释了我之前所有失败的形状实验：
- `(6D 输入, 5D 网格)` 被拒，是因为 6D 输入的网格末维**必须是 4**，而 5D 网格是 3
- LivePortrait 传的 `(5D 输入, 4D 三坐标网格)` 形状是**自相矛盾**的：
  5D 输入要求网格也是 5D，但网格是 4D

## 也就是说

**LivePortrait 这个调用本身就处在一个形状自相矛盾、未被文档化的分支上。**
torch 接受了它（校验只查 `grid.size(-1)`，没查 `grid.dim()` 对不对），
ONNX 导出器则无法处理。

**要导出，就必须复现 torch 在这个歧义分支上的真实行为 —— 而这正是我测不出来的东西。**

## 第 9–10 轮：轴语义已标定并**推翻**了我上一轮的结论

工具：`tools/calibrate_grid_sample.py`（可复现，`--depth` 可指定）

**正确探针方法**（关键，我在这上面错了两次）：把测试坐标放在**一个**网格位置，
其余位置填哨兵值（`9.0`，远在 `[-1,1]` 外），然后**读同一位置**。

**错误一**：第一版把整个网格都填成测试坐标、又去读 `o[0,0,0,0,0]`。
网格会被广播到整个输出张量，那个位置根本不是我以为的点 → 得出"真三线性"的**错误**结论。

**错误二**：用 `D=2` 标定。**D=2 时两个边界效应会混叠到同一个值域**，
读数看起来无法解释（我读到 z=-1 → 5.5，而它不是任何格子的凸组合），
于是我**又一次**错误地断言"z 轴不符合标准"。

### 修正后的结论：**三个轴都符合标准**

`index = (coord + 1) * S / 2 - 0.5`（`align_corners=False`）

`D=4` 的细扫（值 = d*100）：

| z | 实测 | 预期 index | 判定 |
|---|---|---|---|
| -0.750 | 0 | 0.000 | ✅ |
| -0.500 | 50 | 0.500 | ✅ |
| 0.000 | 150 | 1.500 | ✅ |
| 0.500 | 250 | 2.500 | ✅ |
| 0.750 | 300 | 3.000 | ✅ |
| **-1.000** | 0 | -0.500 | 边界填充 |
| **1.000** | 150 | 3.500 | 边界填充 |

**唯一的偏离发生在 `|z| = 1`**，即坐标越出 `[0, D-1]` 时，
torch 的 **zero-padding** 规则生效（越界邻居贡献 0）。
**这是边界规则，不是另一种缩放。**

**用真实深度 `D=16` 复验：无任何内部不匹配点。**

### 这意味着什么

**替代采样函数是可以写出来的**：标准的 `align_corners=False` 映射 + 零填充。
上一轮我写的"z 轴不可解释"是**错的**，路线并未被堵死。

## 第 12 轮：把采样器的失败**定位到一条确切的规则**

第 11 轮那个"自相矛盾"的现象（手算对、模块错）**已找到原因**：

### `torch.gather` 要求索引张量与输入张量**维度数相同**

torch 2.1 实测报错：

```
RuntimeError: Index tensor must have the same number of dimensions as input tensor
```

我两版实现都违反了它：

| 版本 | 问题 |
|---|---|
| v1 | 第一次 gather 用 5 维索引，第二次却用 4 维（因为 `yc`/`xc` 带着网格形状 `(B,Dout,Hout,Wout)`）|
| v2 | 三次都构造成 `(B,C,Dout,Hout,Wout)`，维度对了，**但仍然与 torch 差 2.7** |

**v2 的意义**：它证明**"维度数相同"是必要条件但不是充分条件** ——
索引的**排布方式**还需要真正推导清楚，而不是靠试。

## 第 13 轮：逐步隔离，精确到一个失败的 gather

按第 12 轮定下的"**测量而非猜测**"顺序执行：

### 步骤 1：单轴 gather ✅ 通过

`gather` 的规则（torch 2.1 实测）：**索引张量与输入张量维度数相同**，
且**非被收集轴的尺寸必须等于输出尺寸**。单轴验证：

| 检验 | 结果 |
|---|---|
| `gather(t, 2, zi)`，`zi` 形状 `(B,C,Dout,Hout,Wout)` | ✅ 与直接索引一致 |
| `gather(t, 3, yi)`，同上 | ✅ 一致 |

### 步骤 2：三角链式 gather ❌ 失败，已精确到具体一步

`B,C,D,H,W = 1,2,4,5,6`，某点 `zi,yi,xi = 3,3,1`：

| 步骤 | 实测 | 期望 | |
|---|---|---|---|
| `s1 = gather(t, 2, zi)` | `-0.142011` | `-0.142011` | ✅ |
| `s2 = gather(s1, 3, yi)` | `-0.142011` | `-0.142011` | ✅ |
| **`s3 = gather(s2, 4, xi)`** | **`0.861504`** | **`0.637618`** | ❌ |

**前两次收集正确，第三次错。** 这就是采样器全部偏差的来源 ——
不是权重、不是坐标、不是零填充，**是第三次 `gather` 本身**。

**注意**：`s2` 与 `s1` 在该点相同（`yi` 恰好取到了同一行），
所以 `s2` 的通过**不能证明 dim=3 的链式收集正确** ——
这一点我一开始误读了，选点时必须避免 `yi == j` 这类退化情形。

### 复现脚本（最小）

```python
import torch
torch.manual_seed(0)
B,C,D,H,W = 1,2,4,5,6
Dout,Hout,Wout = 4,5,6
t  = torch.randn(B,C,D,H,W)
zi = torch.randint(0,D,(B,C,Dout,Hout,Wout))
yi = torch.randint(0,H,(B,C,Dout,Hout,Wout))
xi = torch.randint(0,W,(B,C,Dout,Hout,Wout))
b,c,i,j,k = 0,1,2,3,4
zv,yv,xv = zi[b,c,i,j,k], yi[b,c,i,j,k], xi[b,c,i,j,k]
s1 = torch.gather(t,2,zi)
s2 = torch.gather(s1,3,yi)
s3 = torch.gather(s2,4,xi)
assert torch.allclose(s1[b,c,i,j,k], t[b,c,zv,j,k])          # passes
assert torch.allclose(s3[b,c,i,j,k], t[b,c,zv,yv,xv])        # FAILS
```

### 下一步（不要再试错）

第 3 次收集前，中间张量的**最后一个轴是 W，但 `xi` 的索引是沿 dim=4 取的** ——
先单独确认 `gather(s2, 4, xi)` 在**已知 `xi`** 下的语义
（例如让 `xi` 全为常数，看取到的是哪一列），再谈组合。
**在这一点搞清楚之前不要写采样器。**

## 第 14 轮：gather 规则已完全确定，但索引排布仍未做对 —— **停止试错**

### 已确定的 gather 规则（torch 2.1 实测，可靠）

对输入 `(B,C,D,H,W)`、输出 `(B,C,Dout,Hout,Wout)`，收集索引张量必须：

1. **与输入维度数相同**（5 维），否则报
   `Index tensor must have the same number of dimensions as input tensor`
2. **非被收集轴的尺寸必须等于输入对应轴的尺寸**，而被收集轴自由
3. 因此正确形状是：
   | 收集轴 | 索引形状 |
   |---|---|
   | dim=2（深度）| `(B, 1, Dout, Hout, Wout)` |
   | dim=3（行）| `(B, C, Dout, 1, Wout)` |
   | dim=4（列）| `(B, C, Dout, Hout, 1)` |

**单轴全部验证通过**（含常数索引与逐位置索引，均与直接索引一致）。

### 但我做不对"从 `(B,Dout,Hout,Wout)` 构造上述形状"

`zc`/`yc`/`xc` 都来自网格，形状是 `(B,Dout,Hout,Wout)`。
要把它变成上表的形状，需要正确的轴变换。**我连续三次失败**，错误分别是：

| 尝试 | 报错 |
|---|---|
| `unsqueeze(1).expand(B,C,Dout,Hout,Wout)` | 广播把 dim1 填成了索引**值**而不是 1 |
| `permute(0,2,1,3).unsqueeze(3)` | `expanded size (4) must match existing (5)` |
| `permute(0,1,3,2).unsqueeze(3)` | `expanded size (6) must match existing (5)` |

**三次都是我算错轴的顺序。** 这已经不是"再试一次就好"的状态。

### 给下一步的明确建议：**放弃 gather，改用扁平化索引**

与其反复推导轴顺序，不如**绕开它**：

1. 把输入摊平为 `(B, C, D*H*W)`
2. 把 8 个角的 `(z,y,x)` 直接算成**线性索引** `z*(H*W) + y*W + x`
3. **一次 `take_along_dim` / `gather` 沿最后一维**完成收集（只需一个索引张量）
4. 再 reshape 回 `(B, C, Dout, Hout, Wout)`

这样只有**一个** gather、**一维**索引，**没有轴顺序可算错**。
这比继续推导三轴链式 gather 更可靠，也更适合导出 ONNX。

**在写出并通过 `main()` 之前，不要再改动 `sample()`。**
